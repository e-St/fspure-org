Initialize a thin control repo (*-org) with Agent Canvas + Grok Build. Product code stays in other repos.

Why your PAT is safe on this page.

This site is static GitHub Pages with no server of ours, so the token is never stored, logged, or sent to e-St.

Your browser talks only to api.github.com, and only to open a branch and pull request on the control repo you named.

Use a fine-grained token limited to that one repo (Contents + Pull requests) with a short expiry, then revoke it once the PR exists.

Without pasting a PAT here: clone OWNER/something-org with gh (already logged in as you), branch init/control-canvas, add AGENTS.md, a short control README.md, .devcontainer/{devcontainer.json,Dockerfile,post-start.sh} (FROM ghcr.io/e-st/bellen:<version>, containerEnv.REPOS = your product owner/name list, PLATFORM=/workspaces/platform, forward only port 8000), .github/dependabot.yml, and .github/workflows/agent.md, push, and open a PR into main. Your own gh login can write workflow files; Actions GITHUB_TOKEN cannot. You can also add those files in GitHub’s web editor on a new branch. The easy path below is optional.

Yes — you create the PAT on GitHub. This page cannot issue one.

Create the token on GitHub

Choose only the control (*-org) repo — not all repositories, not the product repos.

This writes AGENTS.md, a short README.md, .devcontainer/* (image ghcr.io/e-st/bellen, port 8000 only), .github/dependabot.yml, .github/workflows/agent.md, and .github/workflows/update-from-bellen.yml (the Update from bellen button) on branch init/control-canvas. It does not merge and does not push to main. Workflows permission is required because GitHub treats those as workflow files.
